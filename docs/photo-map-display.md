# MCP 사진·지도 표시 수정 결과

검증일: 2026-11-20. 변경은 `codex/mcp-photo-map-display`에 있으며 운영 서버 재배포는 수행하지 않았다.

## 확인한 원인과 실제 조회

- 기존 갤러리는 초기 `window.openai.toolOutput`에서 최상위 `photos`만 읽었다. 같은 검증 사진을 `visuals.photos`에 넣어 기존 HTML을 실행하면 이미지 요청 0건, 수정 HTML에서는 1건이었다. 이는 실제 코드 실행으로 재현한 입력 형태 문제이며, 사용자가 겪은 ChatGPT 세션의 원본 이벤트를 확보한 것은 아니다.
- 기존 MCP 해설 응답에는 지도 좌표와 지도 링크가 없었다. 홈페이지는 좌표가 없을 때 서울 도심의 고정 핀 링크를 제공했고, 좌표가 사라졌을 때 이전 마커가 남을 수 있었다. SDK의 `maps.load()` 동기 예외도 즉시 처리하지 못했다.
- 사진 표시 정책의 대체 URL 검사가 표시할 URL 대신 원본 URL을 검사했다. 이를 해당 원본에 연결된 표시 URL만 통과하도록 수정했다. 원본·권리 검증과 프록시 허용 도메인을 확대하지 않았다.
- 운영 MCP `search_place`로 **서울특별시 성동구 왕십리로 410 (하왕십리동, 센트라스)**, 지번 **하왕십리동 1070**, 건물관리번호 `1120010200108420000000001`을 확인했다. 토큰 없이 주소 필드만 테스트 fixture로 보관했다.
- 운영 MCP 첫 사진은 `seoul-museum-5039`, **청계천과 무학로에 접한 주거지역**, **2009**, 서울역사박물관 · 서울생활문화자료조사였다. 원문과 이미지 모두 `fileId=H-TRNS-8010-387`, `fileSn=300`으로 연결된다. 이는 **하왕십리동 배경 자료**이며 센트라스 직접 사진이라는 근거가 아니다. 해당 주소의 센트라스 직접 사진은 이번 검사에서 확인되지 않았다.
- 이 첫 사진의 원본·프록시 HEAD는 HTTP 200, `image/jpeg;charset=utf-8`이었다. 실제 프록시 처리기로 GET도 실행하여 HTTP 200, JPEG 서명, **59,505바이트**를 확인했다. 모든 운영 사진의 현재 접근성을 전수 검사한 것은 아니다.
- 운영 홈페이지 `/api/map-config`는 JavaScript 키를 반환했고 `/api/status`는 지도·좌표 설정을 사용 가능으로 보고했다. 해당 공개 키로 SDK 요청은 HTTP 200, `text/javascript`였다. **카카오 콘솔의 도메인 허용 상태, 실제 브라우저 지도 생성, 센트라스 실시간 REST 좌표는 검증하지 않았다.** SDK 다운로드 성공을 지도 사용 권한 확인으로 해석하지 않는다.

좌표는 `latitude = y`, `longitude = x`다. MCP 지도 핀은 기존 공식 주소·지번 대조를 통과한 카카오 로컬 API 좌표만 제공한다. 지도 클릭 지점 자체를 건물 주소의 검증 좌표로 승격하지 않는다. 지도 검색 링크는 좌표가 없는 상태에서도 제공할 수 있다.

이미지 프록시의 HTTPS·도메인·등록 사진 제한, 리다이렉트 차단, MIME 및 실제 바이트 서명 검사, 크기 제한, 권리 검증은 유지했다. 새로운 사진 저장소나 AI 호출은 추가하지 않았다. BigQuery, D1/R2, MCP 도구 이름과 기존 필드는 유지했고 지도 정보는 추가 필드다. 추가 라이브러리·환경변수는 없다. 기존 `KAKAO_JAVASCRIPT_KEY`와 `KAKAO_REST_API_KEY`를 사용한다.

## 배포와 별도 확인

이번 변경을 사용하려면 **MCP 서버와 홈페이지를 각각 재배포해야 한다**. 브랜치/PR 작성은 운영 배포가 아니다. 앞선 미병합 작업 #63 → #64 → #65 위에 쌓인 변경이므로 이 의존성을 유지하여 검토해야 한다.

재배포 후 새 도구 결과에서 `structuredContent.photos`, `structuredContent.map`, 갤러리 v6 제공 여부를 확인한다. 클라이언트가 도구·리소스를 캐시했다면 연결 새로고침 또는 재연결 후 새 대화에서 재검사한다. 기존 v4·v5 리소스 요청도 호환 처리하지만 클라이언트 자체 캐시 갱신은 서버가 보장하지 않는다.

ChatGPT에서 동일 주소를 검색하여 사진 ID·제목·2009년·기관·원문이 한 자료로 표시되는지, 동네 배경 표시가 유지되는지, 이미지 실패 시 다른 검색 사진 없이 원문 링크가 남는지 확인해야 한다. MCP Apps 지원 여부·호스트 CSP·캐시 상태에 따라 갤러리가 다르게 동작할 수 있다. **ChatGPT 자체 지도 렌더링은 MCP 서버가 제어할 수 없으며, 외부 지도 링크가 기본 대안이다.**

홈페이지는 실제 운영 도메인에서 SDK 마커·오류 메시지·외부 링크를 확인하고 카카오 콘솔에 그 도메인이 등록됐는지 별도 확인해야 한다. 설정 기준은 [카카오 지도 JavaScript 가이드](https://apis.map.kakao.com/web/guide/), 좌표 API 기준은 [카카오 로컬 API 문서](https://developers.kakao.com/docs/latest/ko/local/dev-guide)를 따른다.
