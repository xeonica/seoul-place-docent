## A. 실제 확인한 문제와 기존 구현

main `6436b56`을 fetch/분석하고 별도 브랜치 `codex/field-docent-experience`를 만들었다. 사진 검증 PR #63 및 기사·영상/D1 승인 PR #64가 미병합이므로 해당 커밋까지 fast-forward해 재사용했다. 이번 PR은 #64 위의 후속 변경이다. main 자동 병합, Production 배포, 운영 D1/BigQuery/R2 변경은 하지 않았다.

- main의 placeRegisterRecords는 건축물·폐쇄대장의 오류를 catch 후 null/빈 배열로 숨긴다. 공식 정보 없음, 인증 오류, 장소 불일치를 구분할 수 없다.
- guidePhotos는 장소명·질문과 제목의 일치로 가점을 준다. 원본 이미지 일치가 확인되어도 피사체가 검색 건물에 있다는 뜻은 아니다. 사진의 원본/권리 보호는 선행 #63을 그대로 사용한다.
- 이야기 작성 지침과 visitSequence/storyThreads는 이미 있었다. 원문 의미 대조와 직접 장소 연결, 개별 주제/현장 관찰의 데이터 계약이 부족했다.
- BigQuery 후보와 현재 D1 검토·감사·철회는 #64를 재사용한다. 후보를 승인 자료로 자동 승격하지 않는다.
- 홈페이지는 API 키가 있으면 장면 해설 API를 자동 요청했다. 자동 요청을 끄고 해당 HTTP API의 신규 운영자 AI 생성도 막았다. 저장된 해설 읽기와 독립적인 기존 수동 번역/요약 기능 자체는 삭제하지 않았다. 이번 MCP/관람 구성에는 운영자 모델 호출을 추가하지 않았다.
- 실제 사이트의 모든 이미지나 현장 피사체를 시각적으로 대조한 것은 아니다. ‘원본 연결 검증’과 ‘장소 내용 검증’을 혼동하지 않는다.

### 이번 원문 확인에서 발견한 보류 1건

claim:E000421의 ‘1961년 산업변화’에 연결된 [한국민족문화대백과사전 성동구 항목](https://encykorea.aks.ac.kr/Article/E0067004)을 실제 조회했다. 추출된 텍스트에서 1961년 및 축산 관련 설명을 확인하지 못했다. 원문 추출의 한계가 있으므로 역사적 사실 자체가 틀렸다고 단정하지 않는다. 원본 조사행은 보존하되 정확한 근거 문단이 재확인될 때까지 화면 해설, pickScenes, 기계 검증에서 보류한다. 원문과 다른 사실을 ‘같은 숫자가 있다’는 이유로 통과시키지 않는 회귀 검사를 추가했다.

검증 단계는 형식, 출처 대응, 장소 관계, 의미적 확인으로 구분한다. 새 승인 claim은 현재 승인과 정확한 문장·날짜·관계·구간을 검사한다. 기존 자유 문단은 숫자/ID 검사만으로 의미까지 확인했다고 표시하지 않는다. 의미 검증은 not_checked, 사용자 AI가 원문과 대조하는 선택 사항이다.

## D. 테스트 및 브라우저 결과

- 집중 검사 **32/32 통과**(새 기능 및 기존 승인/MCP 통합).
- 전체 **377개 중 360 통과, 17 실패**. 선행 #64의 실패 17개와 이름이 같고 새 실패는 없다. 데이터 수/해시 및 async API 테스트의 기존 불일치를 삭제·완화하지 않았다. 전체 회귀 통과 조건은 미충족이다.
- 공개 MCP 실제 로컬 HTTP/패키지/사진 프록시 **3/3 통과**.
- TypeScript 독립 검사, Next/Vercel 및 공개 MCP 패키지 빌드가 통과했다. Sites/Cloudflare 빌드도 통과했다. 두 프레임워크가 생성 타입 경로를 공유하므로 순차 실행한다.
- 새 주소 캐시가 관리자 지역 검토에도 사용되면서 생긴 회귀를 발견했다. cache는 MCP 검색에서만 opt-in하고 지역 검토는 fresh 조회로 유지해 관련 **22/22** 검사를 통과했다.
- 브라우저: 기록된 실제 주소 응답을 쓰는 로컬 테스트 서버에서 세림아파트 검색/선택, 관람 주제, 접힌 출처와 펼친 원문 링크를 확인했다. 1280x900 및 390x844 viewport를 검사했고 모바일 horizontal overflow는 false였다. 실제 휴대폰 기기/TTS/지도 원문/기관 전체 이미지의 시각 일치는 검사하지 않았다.
- 출처 보류 1건을 마지막에 추가한 뒤 브라우저 재접속은 연결 오류로 실패했다. HTTP는 200이었으나 브라우저 경로가 접속하지 못했다. 따라서 보류 정책의 최종 적용은 자동 검사로 확인했으며 최종 브라우저 재검증을 성공했다고 표시하지 않는다. 저장한 화면은 해당 보류 패치 전 UI 검증 화면이다.
- 선택 파일 ESLint는 기존 DocentStory의 set-state-in-effect 오류 1건 때문에 실패한다. 선행 #64 파일을 stdin lint로 확인해 동일 오류를 재현했다. 경고도 남아 있으며 lint 전체 통과로 보고하지 않는다.
- 로컬 Dev의 기본 Turbopack은 외부 node_modules junction 때문에 실패해 기존 webpack 모드로 확인했다. 127.0.0.1 dev asset origin 차단은 localhost로 접근해 최초 검증했다. 보안/방화벽 설정은 변경하지 않았다.
- 건축물대장/폐쇄대장 실연결: 운영 MCP는 빈 결과여서 정상 연결을 증명하지 못했다. 새 코드의 정상/인증 누락/일부 실패/정확한 필지 필터는 fixture 테스트다. 운영 키 변경, BigQuery SQL 실행, D1/R2 내용 변경은 하지 않았다.

실행 명령과 로그는 outputs/field-*-tests.log, field-typecheck.log, field-next-build.log, field-sites-build.log, field-public-build.log, field-*-benchmark.log에 남긴다. 개발 서버의 테스트용 JUSO 응답은 운영 키와 분리되며 token은 기록 파일에 저장하지 않았다.
