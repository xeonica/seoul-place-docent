# 서울 동별 역사사진 검색·표시 점검

확인일: 2026-11-22
대상: PR #81 브랜치 `codex/history-photo-preview`

## 결과 요약

- 서울시 공식 행정동·법정동 매핑을 읽어 25개 구, 행정동 427곳, 법정동 467곳의 검색 범위를 만들었다. 기존 저장소 법정동 목록 467곳과 구별 이름을 대조했으며, 동 목록은 모두 일치했다.
- 표시권한·이미지 URL·원문 URL이 갖춰진 기존 색인을 검색해 법정동 416/467곳, 행정동 417/427곳에서 해당 범위의 사진 후보를 찾았다.
- 법정동 51곳과 행정동 10곳은 해당 동 색인 사진이 없어 구 단위 배경사진으로 확장했다. 서울 전체에서 해당 구의 이미지 URL 후보를 찾지 못한 동은 0곳이다.
- 894개 동 행을 위해 선택한 대표 사진 URL 325개를 실제 HTTP로 요청했다. 894개 행 모두에서 이미지 응답을 확인했다. 동일 구 대체 사진은 여러 행에서 같은 원본 URL을 재사용할 수 있다.
- 이 검사는 동별 대표 URL 1개씩의 HTTP 응답 검사다. 각 동의 모든 사진 URL이나 실제 ChatGPT 화면의 렌더링 성공을 뜻하지 않는다. 그 이유로 CSV의 성공 상태도 `HTTP 이미지 응답 확인 · MCP/UI 미실증`으로 기록했다.

## 코드 동작

- `prepare_place_answer`는 기존 승인 직접 장소 사진을 먼저 유지하고, 이어서 지역 사진 색인에서 같은 법정동 또는 공식 매핑된 행정동의 후보를 최대 8장까지 보충한다.
- 동 자료가 없으면 같은 구 자료로 범위를 넓힌다. 인근 좌표 자료는 현재 색인에 신뢰할 만한 촬영 좌표가 충분하지 않아 임의로 만들지 않는다. 자치구 사진이 없는 경우의 서울 전체 대체도 추측으로 수행하지 않는다.
- 응답의 사진은 모두 설명용 참고 이미지다. `verificationStatus`를 `source_metadata_only`, `formalEvidenceApproval`을 `unchanged`로 두며, 사진을 건물·필지 직접 근거로 승격하지 않는다.
- `/img` 프록시 원본이 `Content-Type`을 누락하면 JPEG·PNG·GIF·WebP·BMP·TIFF·AVIF 시그니처를 확인한 경우만 이미지 MIME을 보완한다. HTML 또는 확인 불가 바이트는 계속 거부한다.
- 갤러리는 프록시 이미지를 먼저 열고 실패하면 같은 자료의 원본 이미지 URL을 시도한다. 둘 다 실패하면 대체 사진 대신 원문 링크를 제공한다.

## 미완료·제한

- 브라우저에서 ChatGPT MCP Apps 갤러리를 실제 구동해 이미지가 화면에 그려지는지 확인하지 않았다. PR 수정 후 Production에 반영되지 않았으므로 운영 화면 성공을 주장할 수 없다.
- 로컬/원격 MCP의 전체 `prepare_place_answer`를 894개 주소에 호출하지 않았다. 894개 행은 색인과 이미지 URL 검증 결과다.
- 구 단위 대체 61건은 동 직접 사진이 아니다(법정동 51 + 행정동 10). 표시 시 자료의 실제 색인 위치를 함께 보여줘야 한다.
- 주소 색인과 매핑은 공식 구/동 범위지만 사진 행 자체의 촬영 지점 및 건물·필지 관계는 별도 검토되지 않았다.
