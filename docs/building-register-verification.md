# 건축물대장 연결 검증 (2026-11-18)

## 원인과 변경

기존 `buildings()`는 표제부를 조회하며 MCP도 `placeRegisterRecords()`를 호출한다. 미연동이 아니라 오류를 `catch(() => null)`로 숨기고 빈 목록으로 반환하는 문제가 있었다. 기존 `place.records`는 호환 목적으로 유지하며 새 `building`은 성공/실패 상태, 현재 표제부, 같은 필지 후보, 총괄표제부를 명시한다. `place.historicalStatus`는 대장 조회 성공만으로 역사 검증을 주장하지 않는다.

- 기존 지번코드 필터를 유지한다. 서울/서울특별시, 괄호 부가정보, 공백 차이를 정규화한다. 다른 도로명이나 도로명 누락은 같은 필지 후보에 남긴다.
- 단일 대장도 이름이 다르면 모호함으로 반환한다. 다동 아파트/대학교는 개별 동을 임의 선택하지 않는다.
- `getBrRecapTitleInfo` 결과는 별도 `recap`에 보관하고 표제부와 합산하지 않는다.
- 표제부 값은 원문 문자열이며 빈 값은 null, 실제 0은 "0"이다. 시공사는 조회하지 않았으므로 null이다.
- 키 누락, 타임아웃, 파싱 오류, 제공기관 오류, 실제 빈 결과를 구분한다. 오류 메시지에 키나 응답 원문을 넣지 않는다.
- `/api/status`의 기존 boolean은 유지한다. 새 `buildingConnection`의 reachable/verified는 미검사 시 null이다. 조회마다 진단 API를 추가 호출하지 않는다.
- `validate_place_answer`의 선택 입력 `buildingClaims`는 `{evidenceId,field,value}` 목록이다. `building_register:<대장ID>`와 필드 값을 재조회 결과에 정확히 대조한다. 모호한 건물은 통과하지 않는다. 문단 의미 검증이나 역사 검증을 보증하지 않는다.
- 캐시는 추가하지 않았다. 인증키 변경이나 서버리스 인스턴스 간 불일치 없이 동작한다. 총괄표제부 조회는 추가 I/O이며 각 요청은 8초 제한, 페이지당 최대 100개·5페이지 제한이다.

## 실조회

기존 로컬 환경파일은 JUSO 키가 있으나 BUILDING_API_KEY가 없다. 비밀값은 출력·복사·커밋하지 않았다. 운영 Vercel 환경의 설정 여부는 이 결과로 판단할 수 없다.

| 대상 | 실제 주소 API | 건축물대장/수치 |
|---|---|---|
| 마장로42길 16 | JUSO_E0014 | 미검증 |
| 삼선교로16길 116 | JUSO_E0014 | 미검증 |
| 중랑천로 20 | JUSO_E0014 | 미검증 |
| 무학로6길 50 | JUSO_E0014 | 미검증 |

정확한 사용승인일·세대수·층수는 확인되지 않았으며 하드코딩하지 않았다. 실조회 재현: Node 22에서 환경을 설정한 뒤 `node --experimental-transform-types --import ./tests/ts-resolver.mjs scripts/check-building-connection.mjs`. 운영 키를 클라이언트에 노출하지 말고 기존 서버 환경에 설정해야 한다.

## 검사

- 관련 자동 테스트 33개 통과: building-info, core, mcp-http-audit, place-answer.
- TypeScript 검사 통과, Next.js Vercel용 webpack 빌드 성공.
- 전체 테스트 첫 실행 319개 중 301개 통과, 18개 실패. 추가된 후보 매칭 검사 1개는 이후 관련 테스트에서 통과했다.
- 수정 전 main 비교 실행: 315개 중 297개 통과, 동일한 18개 실패. 자료실 API를 동기 호출하는 과거 테스트, 갱신된 데이터 건수와 오래된 기대값, 원본 파일 해시/줄바꿈 불일치, 기존 이미지 이용권한 기대값 문제이다. 테스트를 삭제하거나 비활성화하지 않았다.
- XML/JSON, 0과 누락, 총괄/개별 대장 분리, 복수 건물, 이름 불일치, 지번 불일치, 주소 표기 차이, 인증 실패, 빈 결과, 파싱/시간초과 오류, MCP 키 누락 시 동네 기록 유지, 정확한 필드 검증을 모의 응답으로 검사했다.

공식 API: https://www.data.go.kr/data/15134735/openapi.do

운영 배포 및 main 병합은 수행하지 않는다. 실제 API 성공 검증은 유효한 주소/건축물대장 인증정보가 있는 환경에서 필요하다.
